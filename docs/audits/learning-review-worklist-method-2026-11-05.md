# 学习单元整单元复核工作队列（方法说明）

## 用途

批次 C 已有命题级证据，但仍缺少整单元覆盖核验。这个工作队列只用于安排人工复核顺序，避免一次面对 247 个单元时只能按章节机械推进。它不修改课程正文、证据、状态、学习记录或题库。

运行命令：

- npm run audit:learning-review-worklist
- npm run audit:learning-review-worklist -- --batch-size=10

脚本读取当前课程 JSON 并向标准输出 JSON。每批默认最多 20 个单元，也可将配置设为 10–20 个；最后一批可能少于 10 个。输出不自动写入仓库。需要留档时，请将输出保存在本机私有审阅目录，而不是把考生答卷或人工评分写进 Git。

## 批次边界

脚本沿用学习单元共享范围：章节导读和五个历史兼容映射不进入叶子单元。只将状态为 partial 的叶子单元纳入待审候选，并将两类不同问题分开：

- 存在显式待核主张的单元留在批次 A，不与 C 混合。
- 存在未认证本地 PDF 来源警告的单元留在批次 B，不与 C 混合。
- 其余 partial 单元进入批次 C 工作队列。

## 排序信号

顺序是确定性的：

1. 命中已知模板句式的教学字段数量，从多到少。
2. 结构有效的命题级证据记录数量，从少到多。
3. 证据记录中最早的复核日期，从早到晚。
4. 学习单元 ID，自然数字顺序。

每个单元附带模板字段名、有效证据数量、记录来源 host 数量、证据日期和非空教学字段数量，方便人工取证时定位。host 数量只描述 URL 元数据，不代表来源独立或权威。

## 当前工作区观察

2026-11-05 对当前 WSL 工作区执行只读扫描时，批次 C 为 247 个单元。其中 204 个至少命中一个已知模板句式信号，143 个命中四个或更多；242 个单元只有一条经过现有证据结构校验的有效命题证据记录。若只看原始 evidence 数组，224 个单元只有一条记录；其中部分单元的第二条记录未通过有效性筛选，因此不能把原始记录数和有效记录数混为一谈。模板信号只统计 why、how、confusions、examFocus、scenarios 五个教学字段，分布为：0 个字段 43 个单元、2 个字段 55 个、3 个字段 6 个、4 个字段 1 个、5 个字段 142 个。

这些统计基于当时工作区中的课程数据（包括尚未提交的用户修改），不是固定基线；后续应以脚本读取到的当前数据为准，不把以上数字写死到测试或自动变更流程中。

## 解读限制

- 模板匹配是已知句式的文本启发式。命中只表示应优先检查教学字段是否真正解释了本知识点，不证明内容错误或不可用；未命中也不证明教学质量高。
- 证据数量、host 数量和日期仅用于整理记录，不判断来源是否权威、独立或确实支持课程主张。
- 排序不是知识质量评分，不是事实正确率，不是人工审核结论。
- 自动队列不修改 partial / verified。每个单元仍需人工列出材料性事实、逐项核对教材/权威来源、记录未解决项和审阅决定。

## 人工复核闭环

按队列逐批处理，每批最多 20 个：

1. 对照指定教材版次和对应页码，列出单元所有材料性事实主张。
2. 检查定义、术语边界、公式与单位、版本日期、适用前提、反例和绝对化表达。
3. 核验 why、how、confusions、scenarios、examFocus、pitfalls 是否真正解释当前知识点；课程自拟情境必须与教材原例明确区分。
4. 记录人工复核人、日期、教材版次/印次、印刷页码、逐项主张、证据范围、未解决主张和 complete / partial / blocked 决定。
5. 只有人工确认全部材料性主张覆盖后，才由人工决定是否更新状态；不得由脚本批量升级。
