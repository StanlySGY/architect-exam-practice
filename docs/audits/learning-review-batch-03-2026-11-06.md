## 逐项复核

| 单元 | 复核发现与修订方向 |
|---|---|
| 10.7.4 | ISO/IEC/IEEE 42010 支持架构描述/结构视图，不是度量方法。组件图只能作为构件和依赖数据的输入；需定义依赖边数、扇入/扇出、循环依赖、耦合/内聚等指标、计算口径、模型完整性和阈值。ISO/IEC 25010:2023 是产品质量模型，不提供组件图到可维护性分数的统一换算公式。 |
| 11.1.2 | SoS 不等于“系统数量多”或普通树状层级。ISO 术语强调构成系统交互产生单体无法实现的独特能力，并以行为/管理独立性区分 SoS 与系统集合。单元—系统—SoS 可作教学层次图，但非充分定义或固定演化顺序。 |
| 11.1.3 | NIST CPS 框架涉及数字、模拟、物理与人员组件及物理/逻辑集成，应用示例包括能源、制造、建筑控制、交通、医疗。课程“智能设计/生产/服务/应用”应标为教材或行业分类，不是 NIST 唯一分类。 |
| 11.2.1 | 跨学科背景不是 AI 系统定义。OECD 2024 定义强调机器系统从输入推断如何生成预测、内容、建议或决策，并可能影响物理/虚拟环境；自主性和部署后适应性因系统而异。不可把 ML/LLM 当作 AI 全部。 |
| 11.2.2 | 欧盟 AI Watch 支持 1950s 基础算法、1970s 符号/专家系统、1990s ML、2010s DL 等历史脉络，也记录 AI 寒冬/复兴。它不是严格线性替代；2020 年来源没有覆盖 LLM，宜把大模型作为近年补充，而非正式统一分期。 |
| 11.2.3 | 分类维度混合：ML/知识表示是方法，视觉/语言/交互是能力或任务，机器人是应用系统形态。OECD 将技术方法与应用领域分开列示；建议按“技术方法/能力任务/应用系统”分层。 |
| 11.3.1 | ISO 8373:2021/IFR 支持实体工业机器人定义；RPA bot 是执行规则任务的软件应用。实体机器人、机器人化设备、RPA 软件机器人、智能服务代理应分开讲，不能把软件 bot 当作物理机器人。 |
| 11.3.2 | “程序控制→示教再现→感知/自主规划/协同学习”可作能力增强示例，但不是所有机器人必经的历史阶段。应拆分控制模式、感知规划、自主程度和协作能力。 |
| 11.3.3 | IFR/ISO 8373 支持机器人术语，不支持“机器人 4.0”为通行标准化代际。应标注为特定产业/教材框架，补来源、定义及其与工业 4.0 的关系。 |
| 11.3.4 | 按智能程度、应用领域、系统结构分类的方向合理，单元已提醒分类轴不同。建议分别举例；“智能程度”应说明自治/能力量表，不能只靠弱/强 AI 标签作工程度量。 |
| 11.4.1 | RFC 9556 中的 edge “近”可指物理、网络拓扑或时延邻近，并相对数据源、决策位置或物理交互而言。边缘不限于网关/基站/服务器清单，终端本身也可能承载计算。 |
| 11.4.2 | RFC 9556 汇总 ISO、ETSI、IIC 等定义/参考模型差异；NIST SP 500-325 讨论 fog/mist 分布式、联邦式模型。应区分 edge、fog、mist、MEC 与 cloud-to-thing continuum。 |
| 11.4.3 | 低时延、节省带宽、本地化、隐私、异构、自治和移动性是潜在收益/驱动，不是每个边缘系统都会同时具备的保证。本地处理不自动带来隐私保护；还增加设备异构、物理接触面、远程更新和一致性管理挑战。 |
| 11.4.4 | 云/边/端职责划分可作参考模式，但不是固定分工。任务放置取决于时延、带宽、数据敏感度、算力、连接、成本和运维能力；边缘也可训练/存储，云可实时服务，端侧也可推理。 |
| 11.4.6 | 当前 NIST 证据只支持按时延、数据与资源约束决定部署，未证明智慧园区、云游戏、监控、工业 IoT 必须用同一边缘拓扑。应逐例解释近端处理理由、数据留存/上云位置及云游戏的互动时延与抖动要求。 |
| 11.5.1 | NIST IR 8356 支持现实实体电子表示及状态视角；ISO 23247 是制造领域框架。“数字模型/虚拟样机→实时孪生→城市”是教学叙事，不是统一历史阶段；实时、全生命周期并非所有孪生的必要条件。 |
| 11.5.2 | “物理实体、虚拟实体、连接、数据、服务”可作入门五元素图，但不是所有标准共同采用的唯一结构。ISO 23247-2 描述制造参考/功能视图，Part 4 规定用户、服务、访问和邻近网络信息交换；应标注课程简化模型而非 ISO 正式五层。 |
| 11.5.3 | 建模、仿真、数据、连接和平台是孪生的使能技术，方向正确但过宽。NIST 2024 资料列出传感器、IoT、云、ML、AI 并讨论复杂性/可信/互操作挑战。不是每个孪生都要包含全部技术，应按对象、数据质量、同步频率、模型精度和用途选型。 |
| 11.5.4 | 现有 evidence 主要覆盖制造业，不能由此覆盖城市、产业、战场等全部场景。应逐行业补一手用例，区分概念验证、试点和生产部署，不将研究存在等同于普遍成熟或同等收益。 |
| 11.6.1 | NIST SP 800-145 对云定义支持充分。讲解应明确五项必要特征：按需自助服务、广泛网络访问、资源池化、快速弹性、可计量服务；区分 SaaS/PaaS/IaaS 三种服务模型和四种部署模型。“自动化管理”不是额外的第六项必要特征，计量也不代表所有服务都按次付费。 |

## 来源清单与适用边界

1. **SoS：** ISO/IEC/IEEE 21839/21840。ISO 在线术语预览强调构成系统交互产生独特能力，并以行为/管理独立性区分 SoS 与普通系统集合。ISO 页面显示 21840 Edition 2 于 2026-09-28 处于 publication 60.00、仍在出版流程；不可提前称为正式发布版。
2. **CPS：** NIST SP 1500-201, [Framework for Cyber-Physical Systems: Volume 1](https://www.nist.gov/publications/framework-cyber-physical-systems-volume-1-overview)。支持数字/模拟/物理/人员组件与物理、逻辑集成，不背书课程中特定四分法。
3. **AI：** OECD 2024, [Updated OECD definition of an AI system](https://www.oecd.org/en/publications/explanatory-memorandum-on-the-updated-oecd-definition-of-an-ai-system_623da898-en.html)。本轮打开 PDF 并视觉检查印刷页 4；定义涉及机器系统、输入推断、预测/内容/建议/决策、物理/虚拟环境及自主性/适应性。后续页将 ML/知识方法与视觉/NLP/语音/决策支持/机器人等应用领域分开列示。
4. **AI 历史：** 欧盟 [AI Watch: Historical evolution of AI](https://op.europa.eu/en/publication-detail/-/publication/6264ac29-2d3a-11eb-b27b-01aa75ed71a1/language-en)，支持 1950s、1970s、1990s、2010s 历史脉络及寒冬/复兴；出版于 2020 年，不覆盖近期 LLM 历史。
5. **机器人：** IFR [Industrial Robots](https://ifr.org/industrial-robots)，引用 ISO 8373:2021 工业机器人定义；美国内政部 IBC [Process Automation FAQs](https://ibc.doi.gov/FMD/rpa/faqs) 将 RPA bot 说明为执行规则任务的软件应用。
6. **边缘：** IRTF [RFC 9556](https://www.rfc-editor.org/rfc/rfc9556.html) 定义边缘相对数据源、决策位置和物理交互的邻近性，并汇总不同组织定义；NIST SP 500-325 [Fog Computing Conceptual Model](https://csrc.nist.gov/pubs/sp/500/325/final) 支持 IoT 雾计算的分布式、联邦式模型。
7. **数字孪生：** NIST IR 8356 [Security and Trust Considerations](https://www.nist.gov/publications/security-and-trust-considerations-digital-twin-technology-digital-twin-technology)（2025-02-14）；NIST [Manufacturing Digital Twin Standards](https://www.nist.gov/publications/manufacturing-digital-twin-standards)（2024-09-24）；ISO 23247-2:2021 [Reference architecture](https://www.iso.org/standard/78743.html) 与 ISO 23247-4:2021 [Information exchange](https://www.iso.org/standard/78745.html)。
8. **云：** NIST SP 800-145 [The NIST Definition of Cloud Computing](https://csrc.nist.gov/pubs/sp/800/145/final)，支持正式定义、五项必要特征、三类服务模型和四类部署模型。
9. **维护性/质量：** ISO/IEC 25010:2023 [Product quality model](https://www.iso.org/standard/78176.html) 用于指定、测量和评价产品质量，不提供“组件图直接换算维护性分数”的规则。
