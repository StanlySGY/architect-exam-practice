# Agent 工作区 UI/UX 参考与取舍

更新时间：2026-11-03

本项目 Agent 工作区主要服务于系统架构设计师备考：配置少量模型供应商与角色，然后执行单体、并行或对战评审任务。参考成熟开源产品的交互模式，但不复制它们依赖的复杂后台能力。

## 参考项目

| 项目 | 重点观察 | 本项目采用的模式 |
|---|---|---|
| [Open WebUI](https://github.com/open-webui/open-webui) | Workspace 将模型、提示词、工具、技能等资源分开管理；模型预设负责复用配置 | 将 Agent 团队、模型供应商、任务工作台拆为独立标签；共享一个明确的保存状态 |
| [LibreChat](https://github.com/LibreChat-AI/LibreChat) | Agent Builder 以名称、模型、指令和能力配置为中心；Agent 可复用 | Agent 角色卡、职责描述、模型绑定、可折叠系统提示词、角色模板 |
| [Sim](https://github.com/simstudioai/sim) | 同一工作区组织 Agent、流程构建、测试和运行观察 | 单独的任务工作台、策略说明、执行反馈和耗时摘要 |
| [Paperclip](https://github.com/paperclipai/paperclip) | 从团队/角色/任务角度组织 Agent，强调工作目标与治理 | 用角色视角组织备考导师、架构评审、资料核查员；在运行前说明调用次数与配置边界 |
| [Langflow](https://github.com/langflow-ai/langflow) | 可视化构建 Agent/流程，并可在 Playground 逐步测试 | 借鉴“配置与试运行分开”的思路；暂不引入节点画布，因为当前后端仅支持单 Agent、并行和对战策略 |
| [n8n](https://github.com/n8n-io/n8n) | 工作流执行记录、状态反馈和节点级观察 | 引入持久任务状态、按序号回放的事件日志、断线重连和单任务取消；不伪造独立 Watchdog 或多节点分布式执行能力 |

## 本轮已实现

1. **工作区分区**：Agent 团队、模型供应商、任务工作台三个独立标签；保存入口保持全局可见。
2. **角色预设**：备考导师、架构评审、资料核查员；模板包含适配本项目的职责和系统提示词。
3. **提示词层级**：角色长期规则收进可折叠高级设置；单次任务输入保持独立。
4. **执行反馈**：根据策略和参与角色估算模型调用次数；真实调用完成后记录本次页面耗时和实际调用数，支持复制全部或单个回答。
5. **配置保护**：仍被 Agent 绑定的供应商不可删除；默认角色被停用后回退到可用角色；未保存配置禁止启动任务。
6. **共享 UI 修复**：DOM helper 正确处理 HTML 布尔属性，避免 disabled=false 仍然禁用控件。
7. **本机任务历史**：结果仅在用户主动点击后保存到当前浏览器，最多 8 条；支持回看、逐条删除和全部清空。
8. **实时执行与恢复**：通过持久任务 API 创建任务并返回 taskId；后台执行与 SSE 订阅解耦，事件写入 SQLite 并带单调递增游标；浏览器断线可用 Last-Event-ID 续传，用户显式取消才会中止任务；P0 的失败角色/评审独立重试仍然可用。
11. **持久任务恢复**：任务记录、状态、事件日志、租约和结果保存在独立 SQLite 表；服务启动后扫描过期租约并有限重排；同一幂等键重复提交不会创建第二条任务。
9. **Router / Worker 任务计划**：本地确定性 Router 在调用模型前生成执行计划；候选 Worker 使用隔离的单次调用上下文，独立任务可并行执行；对战评审作为显式依赖步骤，至少两个候选成功后才启动。
10. **结构完整性门禁**：Worker 和评审输出必须满足非空答案、置信度范围及要点/关注点数组契约；失败项标记为不可采纳并保留失败原因。该门禁只检查结构，不证明内容事实正确。

## 能力边界

- “预计调用次数”是按当前策略和参与角色计算的调用数，不代表金额或 token 费用。
- Agent 结果默认不保存；主动保存的最多 8 条记录仅存在当前浏览器的 localStorage，不做应用层加密、不进入服务端 SQLite、不跨浏览器/设备同步，也不具备全文搜索。界面提示用户不要保存密码、API Key 等敏感内容。
- 持久任务执行与 SSE 请求生命周期解耦：浏览器断开只停止事件订阅，不取消后台任务；可使用 Last-Event-ID 从事件游标恢复订阅。取消必须显式调用取消 API。
- Agent API 默认关闭；需要在启动环境显式设置 `ARCHITECT_ENABLE_AGENTS=true`。本机默认回环监听适合个人使用；远程监听必须配置访问令牌。
- 服务端任务与事件保存在本机 SQLite，终态任务保留 7 天；进程重启后，租约过期任务会重新排队，最多执行 2 次（首次 + 1 次恢复）。这采用有限至少一次语义，崩溃边界可能导致模型调用重复，不能承诺 exactly-once。任务事件只对创建者身份可见；远程认证时以访问令牌 SHA-256 摘要作为任务归属键。
- 角色模板只创建本地草稿；只有用户保存工作区后才会写入本机模型配置。
- 当前 Router 仅按单体/并行/对战策略进行本地确定性规划，不额外消耗模型调用；Worker 仍由当前配置的 Provider 执行，不具备自主工具调用或动态模型选择。
- 当前质量门禁只验证输出结构与完整性，事实核验仍需依赖教材、正式资料、来源证据或人工复核。
- 当前任务结果不会自动写入题库、学习记录或错题数据。
- 本项目采用轻量本机架构，优先改善角色与任务体验，不直接引入大型工作流平台的服务端依赖。

## 后续可评估方向

- 后续可独立评估 Watchdog 进度停滞检测、任务优先级/并发 Worker 池、死信人工接管和跨设备长期审计；当前单进程后台执行器不等同于多节点分布式调度。
- 浏览器主动保存的 8 条本机历史仍只存在 localStorage，与服务端七天任务运行记录是两套不同存储；未来可再增加导出、搜索和加密备份。
- 模型调用 token/费用统计（只有实际 provider usage 数据可得时才显示金额）。
- 角色模板导入/导出与社区模板（需定义可信来源和提示词安全边界）。
