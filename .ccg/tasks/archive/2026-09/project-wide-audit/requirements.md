# 审查范围

- 完整盘点项目定位、技术栈、目录结构和运行入口。
- 审查后台 UI/UX、信息架构、交互反馈、响应式布局和核心操作效率。
- 梳理练习、错题、案例、论文、知识库、资料、模型/Agent、题库和数据管理闭环。
- 检查边界处理、权限、安全、性能、可扩展性、测试和半成品功能。
- 所有问题必须提供具体文件或代码位置证据，并按 P0/P1/P2 分级。

## 本轮实施范围

本轮优先落地审查报告中的 P0/P1 风险，不进行整体 JSON 存储迁移、服务层组合式重构或 `public/app.js` 大规模拆分。交付边界包括：

- 非回环监听必须配置访问令牌，管理 API 统一鉴权；Agent HTTP 执行默认关闭。
- 模型列表请求限制协议、主机解析、私有地址、重定向、超时和响应大小；HTTP 配置不能修改 Claude CLI 可执行路径。
- 模拟考试服务端记录截止时间和提交状态，超时判卷只使用服务端已保存答案；判卷状态转换具备并发保护；客户端按题目串行保存并携带 revision。
- 论文模拟草稿保存和 AI 评分在服务端执行截止校验。
- 备份导入校验 schema、集合大小、字段、ID、时间和主要跨集合引用，并通过事务更新；数据导入、导出和清空写入审计日志。
- 为以上行为增加离线单元测试，保留现有本地单用户模式和旧备份版本兼容性。
