# 实施计划

1. 盘点：用户 SQLite 有 2160 题，其中 213 道生成题；第 7、11–15、17–20 章没有生成题。20 章导图均存在。现有 3210 服务持有数据库的内存快照；补题只能经该进程 API，不从其他进程直接改 SQLite。任何写入前导出完整备份到用户目录的私有文件。
2. 后端工作域（独占 `src/service/review.mjs`、`src/service/case-exam.mjs`、`test/practice.test.mjs`）：更正每日目标只统计已答题，并明确本地日界线；在服务端禁止案例考试超时后新增或修改草稿，确保到期已有草稿可判分且不让放弃状态被重新判分；补回归测试。
3. 前端工作域（独占 `public/index.html`、`public/styles.css`、`public/app.js`）：改善空题库初次引导、禁用不能开始的模拟卷，补页面标题和窄屏导航可发现性；考试倒计时与后端规则相匹配，不引入无关功能。
4. 主线：先用隔离临时数据库 + 当前配置模型试生成第 7 章少量题，检查题干/选项/答案/解析/来源完整性；成功后经在线服务 API 分章节/难度增加导图生成题，至少令 20 章各拥有不少于 20 道（过滤重复后统计）；仅补齐不足、保留所有现有记录，失败记录原因可续跑。优先覆盖小节而非单章重复生成。
5. 对新增题做批量结构/来源节点/同章近重复筛查，抽检部分答案与导图；对失败/不可信内容停用或重生，不把模型题冒充历年真题。
6. 集成全套测试及浏览器端到端冒烟，确认真实题库覆盖。进行 antigravity+Claude 双模型审查（若外部服务可用），记录不可用限制、剩余风险并归档，不擅自提交现有未提交改动。
