# 实施计划

## 阶段一：结构与视觉基础

1. 在 `public/index.html` 增加侧栏底部状态区、资料阅读布局语义、知识图谱画布/详情层，以及多供应商和 Agent 配置区域。
2. 在 `public/styles.css` 统一工作台布局、正常内容最大宽度、资料双栏 sticky、图谱独立滚动、抽屉/对话层、响应式断点和状态样式。

## 阶段二：前端行为

1. 更新资料加载和选择逻辑，让目录保持当前项并在阅读容器内稳定工作。
2. 将知识图谱节点从页面跳转改为详情层，保留条目定位入口并恢复原滚动位置。
3. 将模型配置改成供应商列表，获取结果写入对应供应商的模型选择项。
4. 增加 Agent 配置的增删改、策略选择、状态展示和 API 调用；保留旧的单模型选择兼容。
5. 更新侧栏状态和导航的动态内容。

## 阶段三：服务端与持久化

1. 在 `src/model-config.mjs` 增加结构化供应商/Agent 配置存储与掩码处理，默认从旧环境变量构造兼容供应商。
2. 在 `server.mjs` 增加供应商模型获取、配置读写和 Agent 配置接口；校验输入，避免返回秘密。
3. 在 `src/generator.mjs` 增加按 Agent/策略解析模型的最小调度层；单 Agent 走原路径，并行/评审在显式请求时执行。
4. 如需学习配置持久化，扩展 `src/store.mjs` 的状态默认值与备份边界，确保旧 SQLite/JSON 数据可读。

## 阶段四：验证

- `node --check` 检查服务端和前端脚本。
- `npm test` 验证现有学习流程与新增配置/调度测试。
- `git diff --check` 与 `node scripts/scan.mjs . --json` 检查格式和视觉反模式。
- 启动服务，用 Playwright 验证桌面/移动端资料 sticky、Wiki 图谱隔离、详情层、模型下拉和 Agent 配置。
- 运行双模型审查；外部模型失败时在 `review.md` 记录失败原因与本地审查结论。
