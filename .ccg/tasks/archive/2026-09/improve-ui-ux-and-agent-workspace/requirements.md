# 需求与验收标准

## 用户目标

- 将现有备考工作区调整为克制、可扫描、以内容和层级为主的工作台风格，参考 killaislop.com/#catalogue，减少装饰性卡片、重复徽章、过度圆角和无意义的视觉噪音。
- 资料页左侧章节目录在阅读长文时保持可见；移动端改为顶部可操作的章节选择，不牺牲正文阅读空间。
- 保留并明确呈现现有 LLM Wiki 能力；普通条目阅读区域与超宽知识图谱画布分离，图谱不再撑宽整个知识库页面。
- 图谱节点点击后在当前视图内打开详情抽屉或对话层，不把页面滚动到很远的条目位置；仍保留从详情回到条目的明确入口。
- 模型配置支持多个供应商；获取模型列表后以可选择的下拉框使用，不能只把模型名拼成文本展示；兼容现有 `ARCHITECT_LLM_*` 配置。
- 引入可持久化的 Agent 配置，允许为不同任务配置多个 Agent，并提供可控的单 Agent、并行回答、比较/评审模式；默认单 Agent，避免无意增加模型调用费用。
- 侧栏的导航、学习进度和模型状态形成上下分区，利用现有空白但不堆叠新的装饰卡片。

## 功能验收

- 桌面端资料页的目录在右侧内容滚动时保持在视口内；点击目录更新当前条目且滚动位置稳定。
- 移动端不强行使用 `position: sticky` 的双栏布局，章节目录可折叠/选择，正文不出现横向溢出。
- 知识库默认内容不超过正常阅读宽度；知识图谱在自己的画布容器内横向滚动或缩放，横向尺寸不会影响过滤器、条目和其他页面。
- 点击图谱节点打开详情层，详情层显示标题、状态、章节、摘要/内容和关联条目；关闭、Esc、点击背景均可返回原视图，不改变页面滚动位置。
- 模型配置可以新增、编辑、删除多个供应商；API Key 不明文回显，掩码值保存时保留原密钥。
- 每个供应商都有独立的 Base URL、API Key、模型选择和获取模型动作；获取成功后模型出现在该供应商的 `select` 中，并可设为默认模型。
- Agent 配置至少支持名称、角色提示词、供应商/模型、启用状态和任务策略；没有配置 Agent 时继续使用旧的环境变量路径。
- 单 Agent 策略只调用一次；并行/评审策略显式显示调用数量或策略，不默认启用。

## 兼容与安全

- 不迁移或覆盖现有题库、学习进度、Wiki 条目和用户未提交的工作区改动。
- 继续通过服务端请求模型接口，API Key 不进入前端持久化明文或模型状态响应。
- 旧的 `ARCHITECT_LLM_BASE_URL`、`ARCHITECT_LLM_API_KEY`、`ARCHITECT_LLM_MODEL`、`ARCHITECT_LLM_MODELS` 配置继续可用，并作为只读兼容供应商或迁移初值。
- 没有外部模型可用时，以本地代码审查、语法检查、测试和 Playwright 验证作为交付依据；外部调用失败原因写入任务审查记录。
