# P2 前端反馈与 API 可靠性改进

## 来源

延续 `.ccg/tasks/archive/2026-09/project-wide-audit/` 中的全项目审查。P0/P1 已完成，本阶段处理统一加载反馈、页面忙碌状态、请求超时和可重试错误。

## 实施范围

- 为共享 API 客户端增加可取消的默认超时，并保留调用方 AbortSignal。
- 为主要列表/详情加载函数提供统一的 `aria-busy` 和加载占位状态。
- 请求失败时提供页面级重试操作，避免只能依赖 Toast。
- 保存、提交和生成操作在请求期间保持按钮禁用及明确进行中状态。
- 只修改前端反馈和相关测试/文档，不进行 `public/app.js` 的整体领域拆分或数据库迁移。

## 验收标准

- 页面加载或请求期间，相关容器可被屏幕阅读器识别为 busy。
- 默认请求超时后返回可识别的错误码，调用方取消不被误报为超时。
- 失败列表有可触发的重试入口，重试不会叠加并发请求。
- 现有功能和 90 个离线测试全部保持通过。
